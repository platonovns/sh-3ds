# Midwich: отдельный checkpoint контента

Статус: подготовка интеграции; аппаратная приёмка не выполнялась. Нового `.3dsx`
нет, default SH Dev Launcher не изменён. Рабочее дерево `school-completion`,
ветка `codex/school-completion`. Исходная точка — восстановленный принятый
`stage11a-cpu-B-src-8c51d74ee1feb7e0`, Core 2 + F1. Точные идентификаторы и SHA
находятся в `3ds_port/reports/school-checkpoint.json` и внутреннем
`3ds_port/build/school-completion/manifest.json`.

## Граница и граф

Аудит выполнен по исходным `MAP_EVENTS`, таблицам callback, карте точек,
спавнам, заголовкам и символьным конфигурациям USA. Полные записи условий,
предметов и направлений: `3ds_port/reports/school-dependency-audit.json`.
События, замки и развилки не заменяются маршрутными костылями.

| Overlay | Содержание | Исходные события без sentinel | Переходы |
|---|---|---:|---|
| MAP1_S00 | Обычная школа: 1F, двор/башня, подвал | 100 | S01, затем S02 по исходным условиям |
| MAP1_S01 | Обычная школа: 2F, химия, пианино, шкафчик | 103 | S00 |
| MAP1_S02 | Otherworld: 1F/подвал, карточка, телефон, бойлер | 120 | S03, S05 |
| MAP1_S03 | Otherworld: 2F/крыша, водосток, библиотека, шкафчик | 102 | S02 |
| MAP1_S04 | Исходный sound-test/debug overlay | 2 | Нормальный граф школы сюда не ведёт |
| MAP1_S05 | Арена Split Head, вступление/смерть | 3 | S06 |
| MAP1_S06 | Возвращённая школа, послебоссовая сцена, выход | 48 | MAP2_S00 |

Новые resident overlay: **S01–S06**. S00 и MAP2_S00 уже были в принятой базе.
S04 включён для замыкания исходного набора, но отладочный вход не добавлен.
Все комнаты внутри этих overlay используют исходные points/events/doors,
включая необязательные помещения и обычные расходники. MAP2_S01/церковь и
дальнейшие главы не добавляются.

## Предметы, Use и головоломки

Сохранены оригинальные Status/Inventory, сортировка/выбор, отображение,
`Inventory_ItemUse → lastUsedItem → Event_Update → mapEventFuncs`, получение
и расход предметов через исходные `Event_InvItemCmd`/`Player_ItemRemove`.

- Обычная школа: Chemical → рука/Gold Medallion; Gold/Silver Medallion →
  башня; исходное пианино, кот в шкафчике, бойлер и переход миров.
  Флаги 71/72/73, 74, PianoPuzzleSolved и отдельные pickup-флаги сохраняют
  исходную зависимость. Пианино не получает автоматического решения.
- Otherworld: Picture Card и дверь с прорезью; Rubber Ball в двух исходных
  точках, водосток/вентиль → Classroom Key; Library Reserve Key, библиотечная
  подсказка, LockerDeadBody → Lobby Key; телефон, бойлерные кольца и вход
  к боссу по флагу 120. Ключи с исходной активацией кнопкой остаются такими.
- Channeling Stone оставлен как исходное необязательное New Game+ событие;
  это не новый основной маршрут и не обход школьных требований.
- K. Gordon Key, запись учительского адреса и карта/церковный колокол после
  босса подключены через S06; следующий сюжетный район не реализуется.

## Враги, сцены и босс

Подключены оригинальные Stalker/Grey Child, Larval Stalker, Creeper и Split
Head; кот и тело из шкафчика используют свои исходные update-функции.
Таблицы Cat/Creeper/LockerDeadBody/SplitHead берутся из существующих
`pc_port/src/*_anim_infos.c` и инициализируются до запуска retail loop.
Они исключены из PS1 DATA aliases: вызываемые адреса должны быть нативными.
Исходные AI, spawn states, анимации, melee/weapon damage и модели не заменены.

Split Head использует исходную арену SU, модель/анимации, init/control/damage,
слабую пасть, сложность, смерть и флаг 131. Вступление устанавливает 130;
оригинальный эффект завершения устанавливает 132 и таблица событий загружает
S06. Debug auto-kill, изменение здоровья или выдача предметов в игровой
сборке не добавлены. Внешний ARM probe содержит только офлайн-фикстуры.

Все callback школьных событий и их вспомогательные модули слинкованы, включая
воду/водосток, эффекты химии, бойлер/арену и послебоссовые сцены. Исходные START
ветки остаются в исходных автоматах событий. Полное воспроизведение каждой
сцены/пропуска на железе пока не подтверждено.

**FMV не реализовано.** S06 запускает `SysState_Fmv`, параметр 14:
`FILE_XA_M4_02490` (сцена после Split Head). Существующий 3DS `open_main`
фиксирует presentation skip; исходный `SysState_Fmv_Update` после возврата
устанавливает 133 и продолжает игровой процесс. Затем callback S06
`func_800D5614` завершает пробуждение, включая ветку START, устанавливает 134,
возвращает камеру и управление. Отдельный новый видеодекодер/обход не добавлен.

Исходные выходы S06: points 1/2 с флагами 140/141 → MAP2_S00, entry 4/3.
MAP2_S00 уже содержит соответствующие post-school ветки по 132/134 и
возвратные двери. Граница задачи — нормальное управление Harry снаружи;
аппаратное подтверждение этой последовательности отложено до совмещения с 11B.

## Изолированные исправления совместимости

- В шести заголовках повторный `.func_68 = sharedFunc_800D2E7C_0_s00`
  исправлен на `.playerStub_F8`: прежде он затирал callback, в том числе
  эффект арены. Размер/смещения effect descriptor проверяются при компиляции.
- Уточнены декларации/приведения BGM, coordinate и callback типов под ARM.
  Возвращаемые значения указанных effect callbacks исходный dispatcher игнорирует.
- `Pc_CommonPickupInRange` и mouse-cursor hook исключены только из 3DS,
  с сохранением исходных PS1 chunk/point проверок и контроллера.
- Старый byte-алиас D_800A99B5 заменён на `g_PaperMapFileIdxs[1]`.
- `game_school_compat.c` содержит исходный `setDrawStp` producer и пустую
  функцию DualShock vibration, аналогичную остальным vibration границам порта.
  GPU decoder/renderer, readback, RGB5, texture cache, GTE и SPU не изменены.

## Сохранение и проверка

Состояние остаётся в исходном `s_Savegame` (636 байт): inventory, eventFlags,
paper maps, overlay enemy states, map/room, положение, world/boss flags.
Новых постоянных портовых полей нет. `MemCard_GameDataCopy`/проверка checksum
и копирование полного исходного record остаются авторитетными. Пользовательская
карта не записывается офлайн-фикстурами.

Результаты компиляции/линковки: внутренний manifest; целевые ARM результаты:
`3ds_port/reports/school-arm.json`. Проверяются таблицы событий, предметный
dispatch, бинарная эквивалентность анимаций, исходное пианино, damage/death
босса и сериализация школьных состояний. Это проверки компонентов с явными
временными состояниями, а не непрерывное прохождение. GPU/audio используют
существующие границы оракула; качество картинки, hit registration/прицеливание,
все варианты START и естественный бой требуют будущего комбинированного теста.

Пройдено 29 адресных проверок: 478 event records, 9 Use triggers, 114 записей
пяти таблиц анимаций (включая две карты Split Head), корректная/ошибочная
последовательность пианино, нативный пакет SetDrawStp, damage/death Normal и
Hard, четыре состояния исходного save record. `make -n` подтверждает правила
компиляции/namespacing новых overlay. При сравнении изменённых существующих
путей с активным checkout и восстановленной 11A B расхождений Stage 11B
в этих путях на момент подготовки не обнаружено; ниже перечислены общие
точки, которые всё равно нужно согласовать при будущей интеграции.

## Интеграция с будущей принятой Stage 11B

1. Использовать **content commit/patch после 6679d655a**, не переносить весь
   восстановительный baseline commit. В архиве checkpoint есть точный patch и
   перечень изменённых путей. Frozen 11A/11B артефакты не перезаписывать.
2. Применить изменения source/header/build tooling. Возможные общие точки:
   `Makefile.game`, `game_map.c`, `game_native.c`, `native_overlay.py`,
   `build_identity.py`, `bodyprog_800881B8.c`, общий BGM include.
   В `game_native.c` требуется только четыре Init; наблюдатели/профилировщик
   Stage 11B сохранить. Renderer и аудио-файлов в content diff нет.
3. Пересобрать новые overlay по `school_sources.mk` и перечисленные bridge
   модули; включить шесть `.native.ld`. При custom relink Stage 11B заменить
   его `game_map`, `game_native`, `bodyprog_800881B8`, добавить шесть overlay,
   четыре animation tables, `pc_timing`, `game_school_compat`. Остальные объекты
   и флаги брать из **принятой 11B**, не из внутреннего 11A ELF этого checkpoint.
4. `tools/build_school.py` воспроизводит только этот исторический внутренний
   ELF из frozen B. Это не команда сборки итогового 11B кандидата. Для
   повторения офлайн: `python3 tools/audit_school.py`, `python3 tools/build_school.py`,
   `python3 tools/test_school_arm.py` в devkitARM-окружении.
5. После завершения 11B создать один совмещённый игровой кандидат с новым
   полным source identity, выполнить штатную публикацию и HTTP SHA/size
   проверку. Только тогда — одно нормальное прохождение с существующего save
   до смерти босса, послебоссовой сцены и управления на MAP2_S00.

Оставшиеся неопределённости: полноценное аппаратное прохождение, визуальные
эффекты новых сцен на оптимизированном renderer, естественный бой и память/
производительность более плотных школьных комнат. Текущий checkpoint не
содержит архитектурных исправлений этих будущих renderer/performance вопросов.
