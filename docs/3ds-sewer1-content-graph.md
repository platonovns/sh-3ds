# Block 4: граф оригинальных событий и границы доказательства

После возврата Block 3 в `MAP2_S02`, вход с event point 24 в `MAP2_S00` имеет две ветви. Когда установлен 191 и не установлен 193, выбирается исходный `SysState_LoadOverlay` с point 33; переход выставляет свой `disabledEventFlag` 193 в `SysState_LoadRoom/LoadOverlay`. Иначе исходная ветвь использует point 25. В `MAP2_S00` событие waterworks требует 193 и отсутствия `EventFlag_M2S00_WaterWorksCutscene`; callback возвращает управление и устанавливает флаг сцены. Точки 62–65 загружают `MAP5_S00` через point 66 `MAP2_S00`.

В `MAP5_S00` обработчик entry, отключаемый флагом 355, отыгрывает вход и возвращает управление. Событие точки 32 позволяет взять бумажную карту (map index 13, флаг 361). Точка 29 — Sewer Key, флаг 353; точка 10 — item trigger этого ключа при 353 и отсутствии map-mark 1371. Исходный dispatcher ставит 1371, callback расходует ключ; после этого события перехода между точками 9/10 используют этот флаг. До открытия отдельное событие сообщает о запертой двери.

Точка 30 запускает оригинальное событие извлечения Sewer Exit Key из воды: в шаге 10 устанавливается флаг 354, добавляется предмет и появляются Hanged Scratcher. Точка 14 принимает предмет при 354 и отсутствии map-mark 1391; тот же dispatcher устанавливает 1391, callback расходует ключ. После открытия переходы между точками 14/15 используют 1391. Точки 23–27 запускают лестничные сценарии; взаимно противоположные флаги 356/357 и 358/359 управляют их продолжением. При 358 и отсутствии 359 автоматический переход загружает `MAP5_S01` через point 31 `MAP5_S00`. Сценарий точки 22 сообщает, что возвращаться нельзя.

Оригинальные события содержат 8 отдельных common pickups и три save-point trigger (34–36), а также двусторонние переходы 3/4, 5/6, 7/8, 9/10, 14/15, 16/17, 18/19 и 20/21 с исходными map-mark условиями. Этот список отражает event table; непрерывное фактическое прохождение, порядок всех областей и save/load в каждом месте требуют отдельного доказательства.

В исходных event tables `MAP5_S00` и `MAP5_S01` нет `SysState_Fmv`; канализационный callback использует статический `TIM_DRAINKEY`, BGM pause/fade и звуковые события. Это проверка таблиц и явно вызванных файлов главы, а не утверждение об отсутствии всех XA-зависимостей в загружаемых данных. Наследуемая зависимость Native-FMV из Block 3 сохраняется.
